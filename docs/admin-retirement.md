# Admin.html 廃止完了記録

`Admin.html` は削除済み。`旧管理画面` サブメニューと `openAdminDialog` も削除済み。通常運用はWebモニター、設定シート、onOpenメニュー、各管理シートへ移行済み。

## 現在の役割

| 場面 | 使う場所 | 方針 |
| --- | --- | --- |
| 授業中確認 | Webモニター | 設定シートの `MONITOR_URL` から表示・履歴参照を確認する。`★ 先生用URLを設定シートに出力` 後は、可能ならモニター表示用キャッシュがbest-effortで初期作成される。書き込み系操作は `モニターだけ更新` と `集計から完全更新` だけに限定する。 |
| 生徒画面テストプレイ | 設定シート | 設定シートの `TEST_STUDENT_URL` を先生が開く。Classroomには配付しない。 |
| 設定変更 | 設定シート | `値` 列を直接編集する。 |
| 準備・配付・保守 | onOpenメニュー | スプレッドシートの `もるくえ！` メニューから実行する。 |
| 個別対応 | onOpenメニュー | `トークン管理` シートの対象行を選択し、`④ 個別対応` から実行する。 |
| ログ・生データ確認 | 各管理シート | `解答ログ`、`配付ログ`、`実行ログ` などを直接確認する。 |
| 表示中一覧CSV | Webモニター | 現在の表示・絞り込み結果の生徒一覧だけをブラウザ側で保存する軽量な表示用CSV。 |
| 成績処理・分析 | 今後の別機能 | 解答ログ全履歴CSV、問題タイプ別詳細CSV、分析CSV、苦手傾向分析、苦手傾向Classroom通知は対象外。 |

生徒APIは常時高速ルートで動く。通常/高速切替設定は存在しない。生徒画面の初回表示と採点レスポンスを優先し、初回アクセス時刻の即時書き込み、採点時の集計キャッシュ更新、問題タイプ別キャッシュ更新を待たない。そのためWebモニターのアクセス済み、解答数、問題タイプ別反映が少し遅れることがある。通常運用は変えず、授業中はまずWebモニターの `モニターだけ更新` を使い、正確に整える必要がある場合は `⑨ 集計キャッシュを更新` またはWebモニターの `集計から完全更新` を使う。

Webモニターは通常、`モニターキャッシュ` の `dashboard` 行に保存された1セルJSONスナップショットを読む。`★ 先生用URLを設定シートに出力` の完了時にも、既存キャッシュからこのスナップショットをbest-effortで初期作成する。初期作成に失敗しても `MONITOR_URL` と `TEST_STUDENT_URL` の出力は成功扱いにする。`モニターだけ更新` は既存キャッシュからWebモニター表示用キャッシュだけを再生成する軽量更新で、授業中にまず使う。`⑨ 集計キャッシュを更新` またはWebモニターの `集計から完全更新` は、解答ログから `集計キャッシュ`、`問題タイプ別キャッシュ`、`モニターキャッシュ` を作り直す重い更新として整合に使う。`snapshot-missing` 時は強調表示された `モニターだけ更新` から復旧し、`モニターだけ更新` で復旧できない場合や人数・集計が古い場合だけ、強調表示された `集計から完全更新` を使う。`集計から完全更新` は重いため授業中は必要時だけ使う。必要に応じて `管理スプレッドシートを開く` で同じ管理ブックを別タブ表示する。通常運用は設定シート、onOpenメニュー、Webモニター、各管理シートのままで、`Admin.html` は復活させない。

授業中にモニター反映を定期更新したい場合は、onOpenメニューの `⑤ 自動更新` を使う。`⑤-1 集計・モニター自動更新を有効化`、`⑤-2 集計・モニター自動更新を停止`、`⑤-3 自動更新の状態を表示` で運用し、通常は5分程度を推奨する。`⑤ 自動更新` はフル更新系で、指定間隔ごとに `集計キャッシュ`、`問題タイプ別キャッシュ`、`モニターキャッシュ` を整える。すぐ表示用スナップショットだけを作り直したい場合はWebモニターの `モニターだけ更新`、解答ログから正確に整えたい場合は `⑨ 集計キャッシュを更新` またはWebモニターの `集計から完全更新` を使う。

## Webモニターで確認するもの

Webモニターの表示・履歴参照は `getMonitorDashboardData`、`getMonitorStudentAnswerHistory`、`getMonitorStudentProblemTypeStats` を使う。書き込み系操作は `rebuildMonitorSnapshotFromMonitor` と `rebuildAggregateAndMonitorCacheFromMonitor` だけを許可する。前者は既存キャッシュからモニターキャッシュだけを再生成し、失敗時は必要に応じて完全更新を案内する。後者は集計キャッシュ、問題タイプ別キャッシュ、モニターキャッシュの完全更新に限定する。CSVは表示中一覧CSVだけで、サーバー関数を呼ばない。

- 生徒一覧
- 生徒ごとの進捗
- 配付済み、未配付、配付失敗
- アクセス済み、未アクセス
- 解答数
- 直近正答率
- レベル別状況
- 最終解答
- 要フォロー
- 生徒別履歴
- 問題タイプ別統計
- 管理スプレッドシートを開く導線
- 表示中一覧CSV

Webモニターから、トークン再発行、URL無効化、Classroom投稿削除、自動更新ON/OFF、初期化、設定保存、同期対象保存は実行できない。`表示中一覧CSV` はサーバー側CSV生成を行わず、現在の検索・絞り込み・ソート後の生徒一覧だけをブラウザ側で保存する表示用CSVである。解答ログ全履歴CSV、問題タイプ別詳細CSV、分析CSVは対象外。

## 各管理シートで確認するもの

- `解答ログ`: 生徒ごとの解答、生徒回答、正誤、問題文、解説、所要時間
- `配付ログ`: URL配付、DRY_RUN、失敗、投稿削除結果
- `実行ログ`: トークン発行、配付、集計更新などの実行単位ログ
- `トークン管理`: 個別URL、最終アクセス日時、無効化状態、投稿削除指定
- `Classroom一覧`: 担当Classroom、同期対象
- `生徒名簿`: Classroom別の生徒情報
- `集計キャッシュ`: 生徒別の集計済み進捗
- `問題タイプ別キャッシュ`: 生徒・level・problemType別の成績
- `モニターキャッシュ`: Webモニター用の自動生成JSONスナップショット

## onOpenメニューへ移管済みの操作

- `⓪ 初期整備・保守` -> `⓪-1 管理シートを作成・補修`
- `⓪ 初期整備・保守` -> `⓪-2 管理データを全削除して初期状態に戻す`
- `① Classroom同期` -> `①-1 Classroom一覧を取得`
- `① Classroom同期` -> `①-2 同期対象の説明を表示`
- `① Classroom同期` -> `①-3 生徒名簿を取得`
- `② 生徒URL` -> `②-1 トークンを発行`
- `② 生徒URL` -> `②-2 配付対象を確認`
- `② 生徒URL` -> `②-3 DRY_RUNでURL配付確認`
- `② 生徒URL` -> `②-4 URLをClassroomに配付`
- `② 生徒URL` -> `②-5 失敗分を再送`
- `③ 投稿・URL取消` -> `③-1 投稿削除=1 のURLを無効化してClassroom投稿を削除`
- `④ 個別対応` -> `④-1 選択行の教師プレビューURLを表示`
- `④ 個別対応` -> `④-2 選択行のトークンを再発行`
- `④ 個別対応` -> `④-3 選択行のURLを無効化`
- `⑤ 自動更新` -> `⑤-1 集計・モニター自動更新を有効化`
- `⑤ 自動更新` -> `⑤-2 集計・モニター自動更新を停止`
- `⑤ 自動更新` -> `⑤-3 自動更新の状態を表示`
- `★ 先生用URLを設定シートに出力`
- `⑨ 集計キャッシュを更新`

## 設定シートへ移管済みの操作

次の設定は `設定` シートの `値` 列を直接編集する。

- `WEB_APP_URL`
- `POST_TEXT_TEMPLATE`
- `CLASSROOM_SEND_BATCH_SIZE`
- `DRY_RUN`
- `ENABLE_DISTRIBUTION_LOG`
- `ENABLE_ADAPTIVE_PROBLEM_SELECTION`
- `BEGINNER_AVOGADRO_CONSTANT`
- `INTERMEDIATE_AVOGADRO_CONSTANT`
- `ADVANCED_AVOGADRO_CONSTANT`
- `BEGINNER_TOLERANCE`
- `INTERMEDIATE_TOLERANCE`
- `ADVANCED_TOLERANCE`

次のURLは `★ 先生用URLを設定シートに出力` で自動出力し、設定シートから開く。先生が直接編集する主設定としては扱わない。

- `MONITOR_URL`
- `TEST_STUDENT_URL`

## 移管済みの個別対応

| 項目 | 状態 | 移管先・運用 |
| --- | --- | --- |
| 個別トークン再発行 | 移管済み | `④ 個別対応` -> `④-2 選択行のトークンを再発行` |
| 個別トークン無効化 | 移管済み | `④ 個別対応` -> `④-3 選択行のURLを無効化` |
| 教師プレビュー | 移管済み | `④ 個別対応` -> `④-1 選択行の教師プレビューURLを表示` |
| 同期対象保存 | 移管済み | `Classroom一覧` シートの `同期対象` 列を直接編集する。 |
| 設定保存 | 移管済み | `設定` シートの `値` 列を直接編集する。 |

個別対応はClassroomへ自動投稿しない。個別再発行後の新URLはalertで確認し、必要に応じて先生が扱う。URL無効化はClassroom投稿自体を削除しないため、投稿も削除したい場合は `トークン管理` の `投稿削除` に `1` を入力して `③ 投稿・URL取消` を使う。

`TEST_STUDENT_URL` は `トークン管理` に作る先生用テスト生徒tokenであり、生徒名簿には追加しない。Classroom配付対象にも配付ログの通常 `SUCCESS` にも含めない。

## 残課題

解答ログ全履歴CSV、問題タイプ別詳細CSV、分析CSV、苦手傾向分析、苦手傾向Classroom通知は今後の別機能として扱う。今回実装済みなのはWebモニターの表示中一覧CSVだけで、分析機能は実装しない。
