# 詳細レビューのGAS実測

## 実行方法

1. 検証プロジェクトへ `scripts/deploy-test-gas.ps1` で反映する。
2. 設定シートの認証付き `MONITOR_URL` を開き、URL末尾に `&benchmark=1` を追加する。認証値入りURLは共有資料・Gitに残さない。
3. 「測定データを準備」を押す。`検証_詳細レビュー_v1` シートに架空の10人・1,200解答を作る。既存の正常な測定シートは再利用する。通常の名簿・トークン・解答ログ・集計には書き込まない。
4. 「測定を開始」を押す。3回は動作確認用、10回は比較用。測定中は同じタブを前面に保ち、他の操作をしない。
5. 「測定結果JSONを保存」で結果を保存し、次のコマンドで判定する。

```powershell
npm run check:review-performance -- <保存したJSONのパス>
```

終了コードは0が成功、1が性能目安超過・操作失敗・測定不足、2が形式不正。JSON内の目安値や集計結果を鵜呑みにせず、生データから再計算する。

## 計測する内容

| 操作 | 暫定のp95目安 |
| --- | ---: |
| 詳細レビューを開き、問題を表示 | 5,000 ms |
| 解答・解説を展開 | 100 ms |
| 不正解に絞り込み | 5,000 ms |
| レベルで絞り込み | 5,000 ms |
| 続きの履歴を追加 | 5,000 ms |

本体のUI処理の開始から、DOM更新後の2回目のアニメーションフレームまでを計測する。これは物理的な画面描画完了を保証するブラウザAPIではなく、描画機会を含めた応答指標である。ページ遷移・GASの初期HTML読み込み・測定データの準備時間は含めない。各操作では内容の条件一致や追加件数、試行IDの重複も確認する。タブが非表示になった測定、20秒を超えた測定、操作結果が不正な測定は失敗として扱い、その時点で中断する。成功した時間だけで中央値・p95・最大値を計算し、失敗と未完了を別に報告する。3回のp95は実質最大値であり統計的な保証ではない。

専用APIは通常の詳細レビューと共通のシート読込・ページ送り・正誤絞込処理を使う。測定用シートの検査時間も含む。通常の管理者認証に加え、指定の検証用Script IDであることを各APIで検証する。測定用の生徒キー以外は拒否する。測定データは合成した履歴であり、出題生成・採点精度のテストを代替しない。

これは単一ブラウザでの反復測定。多数の生徒が同時接続する負荷試験ではない。通信とGAS実行時間には揺らぎがあり、5秒を保証するものではない。最初の操作も除外せず保存するが、GAS内部のコールドスタートを強制する仕組みはない。

## 計測器の自動テスト

```powershell
npm run test:review-performance
npm test
```

前者はローカルのブラウザと疑似GAS応答を使い、計測器が通信待ちを含めること、失敗を記録すること、測定データが既存ログに混ざらないことを検査する。このコマンドの時間をGASの実測値として扱わない。`npm test` は結果判定コマンドを含む全234テストを実行する。

生データの `actionElapsedMs` は通信とDOM更新を含む操作処理時間、`frameWaitMs` はその後のフレーム待ち時間を表す。両者の合計を `elapsedMs` として判定する。フレーム待ちだけが大きい場合はブラウザ環境の影響も切り分け、アプリの計算処理がその時間を消費したとは断定しない。


## GAS実測結果（2026-09-06 / deployment version 11）

Chrome、ビューポート1,897×831、各操作3回。15操作すべて成功。これは単一端末での実測であり、多人数同時接続試験ではない。

| 操作 | 中央値 | p95 / 最大 | 性能判定 |
| --- | ---: | ---: | --- |
| 詳細を開く | 3,034 ms | 3,282 ms | PASS |
| 解説を展開 | 2,017 ms | 2,032 ms | FAIL |
| 不正解で絞込 | 3,067 ms | 3,150 ms | PASS |
| レベルで絞込 | 4,017 ms | 4,350 ms | PASS |
| 続きを読む | 3,584 ms | 4,050 ms | PASS |

解説展開の `actionElapsedMs` は3回ともms単位の丸めで0、`frameWaitMs` は29 / 2,017 / 2,032 msだった。約2秒は展開処理の実行時間ではなく、後続のアニメーションフレーム待ちとして観測された。ブラウザのフレーム配信が遅れる原因までは特定していない。判定を通すための閾値変更・失敗除外はせず、性能チェックの終了コード1として残した。

最初のversion 10では詳細取得に5,266 msも観測された。実装・計測器の自動テスト234件は成功しているが、描画待ちを含む性能目安は未達。再測定時には通信待ちとフレーム待ちを分けて比較する。
