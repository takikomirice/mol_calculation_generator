# 管理操作を90点へ近づける設計

目的は授業中の確認・連続レビュー・準備や個別対応への移動を短くすること。ユーザーは実装、検証用GAS反映、ブランチへのcommit/pushを許可済み。自学自習の仕様と採点経路を維持する。

## 比較した構成

1. モニターに管理操作の案内と直接リンクを加える（採用）。日常レビューを1画面で続け、必要時だけ該当シートへ移る。
2. 管理画面を独立して復活させる。画面と認証・書込み経路が増え、既存運用の整理に対して過大。
3. 手順書だけ整理する。実装は小さいが毎回の画面移動を減らせない。

## 操作の仕様

- 一覧に表示件数と適用中の条件を表示し「絞り込みを解除」で検索・Classroom・状態・チェックを解除する。表示モードと並び順は維持する。
- 表示モード、並び順、Classroom、状態、チェックを同じタブで再読込後に復元する。sessionStorageを使い、ブック別・検証画面別に分離。検索文字列・氏名・認証値・履歴は保存しない。保存不可や古い値でも表示可能。ClassroomはIDで区別し、同名クラスはIDを併記する。
- 詳細レビューに「前の生徒」「次の生徒」と一覧内の位置を表示。開いた時点の絞り込み・並び順で対象を固定し、自動更新で順番が変わらない。正誤・レベル条件を維持。別の生徒へ移ると履歴と統計を入れ替え、古い応答を無視する。端では該当ボタンを無効化。閉じると元の一覧ボタンへフォーカスを戻す。
- 既存の「管理スプレッドシートを開く」を「管理操作」へ変更し、必要時にネイティブdialogを開く。準備・配付、個別対応、設定、確認の目的別に、実在するシートへのリンクと短いメニュー手順を表示。ブック全体を開くリンクも残す。
- レビュー内の「この生徒の管理」からは対象氏名を示し、該当するトークン管理・名簿の行へリンク。行がない場合は代わりの生徒を出さず、その旨を表示する。シート側で氏名を確認して操作する案内を付ける。
- 管理操作APIは管理者認証後に固定の管理シート名のみ参照し、リンクと利用可否のみ返す。解答ログや設定値、トークン、個別URLを返さず、書込みやClassroom通知を行わない。通常の更新には呼ばない。
- 読込中・失敗時の再試行・閉じた後の遅延応答を扱う。リンクはhttps://docs.google.com/spreadsheets/d/から始まる検証済みURLのみ有効化。dialogのEscapeとフォーカス復帰、390px画面を確認。

## 合格条件

同名クラスの分離、絞込復元と解除、絞込済みの連続レビュー、通信失敗・遅延応答、管理者以外のAPI拒否、欠落シート・対象行なしをテストする。連続レビューは次の生徒へ1操作、目的のシートへは管理操作を開いてリンクの2操作とする。通常更新に追加API呼出し0件。全テストとCI成功、実GASで管理ガイド・レビューを操作し、レイテンシと操作数を記録する。新しい操作だけで90点を断言せず、実授業・配付本操作・端末差の未検証を減点に残す。
