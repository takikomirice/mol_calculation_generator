## 更新ボタン統合（2026-09-06）

教員画面の更新操作を「更新」1つに統合。従来の「モニターだけ更新」「集計から完全更新」は画面から削除し、確認ダイアログも省いた。自動更新も同じ差分集計を呼ぶ。全履歴の修復は管理シートの「⑨ 集計キャッシュを更新」に残す。

- 前回までの集計位置と生徒別の件数・レベル別正答数・直近10問などを `モニターキャッシュ` の `refresh-state:*` 行へ分割保存する。集計位置と結果は同じ書き込みで保存する。
- 通常は新規追記分のみを処理する。初回・復旧・大量の追加は最大500行ずつ進め、画面へ進捗率を表示する。書式用の空行も読み飛ばしながら確認するため、処理行数は解答件数とは異なる。
- キャッシュが消失しても保存済みの位置から復元する。ログが縮んだ場合や先頭・処理済み末尾の試行IDが変わった場合は作り直す。途中の古いログを手修正した場合は「⑨ 集計キャッシュを更新」後に画面の「更新」で再集計する。
- 名簿、URLの無効化、配付状況は毎回読み直す。更新開始後に追記された解答は次回の更新で拾う。
- 更新中はボタンを無効化し、一覧・検索条件・並び順を保持する。失敗しても前回の一覧と反映時刻を残し、同じボタンで再試行できる。
- 100人・5,003解答のローカル検証で、全件集計と件数・正答率・レベル別件数・直近10問・時間指標が一致。追記1件では1行だけ読むこと、途中保存の失敗、再試行、同時更新の拒否、ログ縮小、分割キャッシュの欠損、権限拒否を確認した。JavaScript実行下のブラウザーテストで更新中・失敗時の表示保持と分割更新を検証した。
- GAS上の教員画面でボタンが「更新」1つになったことと、保存済み解答の差分確認完了を確認。通常更新の観測値は3,241 / 3,367 / 2,881 / 3,708 ms。最終版はdeployment version 8へ反映し、全229件のテストが成功した。旧来の保存済み表示だけを読む更新とは異なり、解答の追加確認と最新の名簿・URL状態の取得を含む。

## 生徒の詳細レビュー（2026-09-06）

ダッシュボードの生徒行にある「詳細レビュー」から専用パネルを開く。一覧には問題を展開せず、パネルでも問題文・正誤・レベル・日時を先に表示する。気になる問題を開くと、生徒の入力、正答と単位、解答時間、保存された解説を確認できる。有効数字不足が記録されている場合は数値間違いと区別して理由を表示する。過去の問題を現在のルールで採点し直さず、保存済みの判定を表示する。

- 正解／不正解、Lv.1〜Lv.6で全履歴を絞り込める。最大20件ずつ表示し、続きを読み込んでも開いた解説を保持する。
- 1回の取得では解答ログを最大500行だけ確認する。該当する解答が少ない場合は20件未満になるため、古い履歴を探すには「続きを読み込む」を使う。先に表示済みのページは、新しい解答の追記で位置がずれない。
- 問題タイプ別の全期間・全レベル集計は、開いたときだけ別に取得する。詳細取得や集計は通常のダッシュボード更新に追加しない。
- 管理者認証を毎回検証し、指定した生徒だけの履歴を返す。トークンや端末情報は返さない。通信失敗時は表示済みの問題を残して再試行できる。
- 対象は解答ログに保存された解答済みの問題。表示後に未解答で閉じた問題や、先読みしただけの問題は含まない。古い履歴に解説・時間がない場合はその旨を表示する。
- ローカルの実ブラウザで、生徒2人・45解答を使って開閉、全文表示、正誤・レベル絞り込み、ページ追加、通信失敗と再試行、生徒切替時の古い応答の破棄、キーボードのフォーカス、390px幅での操作を検証した。1,205行のAPIテストでは生徒の分離、取得範囲の上限、入力の有効数字保持、認証拒否を確認した。全231テスト成功。
- テスト用GASのdeployment version 9へ反映。GASの教員一覧は実生徒未登録のため0人であり、データのある詳細パネルの検証はローカルのブラウザテストで実施した。詳細取得のGAS実測時間はまだ測定していない。
