# 現行版のスプレッドシート構成

現在の管理者・生徒画面（Lv.0〜8）に必要な管理シートは10個、設定は10項目。未リリースの旧3段階用設定・集計列は保持せず、「管理シートを作成・補修」で除去する。

| シート | 必須列数 | 役割・編集対象 |
| --- | ---: | --- |
| 設定 | 4 | キー・値・説明・更新日時。値列で運用を設定 |
| Classroom一覧 | 6 | Classroom同期結果。同期対象は1／空欄 |
| 生徒名簿 | 8 | Classroomごとの生徒と在籍状態 |
| トークン管理 | 14 | 個別URL・無効化・投稿削除指定 |
| 解答ログ | 24 | 解答の正本。問題文・入力・正答・判定・解説・時間 |
| 配付ログ | 10 | 配付・取消の実行結果 |
| 集計キャッシュ | 53 | 生徒別総数・直近10問・Lv.0〜8・時間指標・autoProgress |
| 問題タイプ別キャッシュ | 21 | 生徒・レベル・問題タイプ別集計 |
| モニターキャッシュ | 4 | モニター表示と差分集計の自動生成JSON |
| 実行ログ | 9 | 管理操作の実行結果 |

キャッシュ3シートは自動生成用。直接編集せず、必要時は「⑨ 集計キャッシュを更新」で再構築する。解答ログの行位置はレビューのページ移動・差分集計に使うため、補修で行を詰めたり並べ替えたりしない。

v4.0.1では、モニターの表示用JSONも30,000文字以下に分割する。大きなJSONは元のkeyに分割数・総文字数のmanifestを保存し、`key:part:0`以降に本文を保存する。同じ一括書込みで置換し、差分集計の`refresh-state:*`や他のkeyを保持する。欠損・重複・更新時刻の不一致があればそのスナップショットを使用しない。小さいJSONは従来どおり1行。シート・列・設定項目の追加は不要。全件再集計後の増分状態リセットは、メニューと自動更新の共通処理で行う。

v4.0.2の一覧の列設定はブラウザー内に保存するため、シート・列・設定キーの追加はない。時間指標の対象件数は既存の差分集計状態から表示用JSONに含める。集計53列への追加や、列の切替時のシート読み取りは行わない。件数を持たない既存集計から表示を作る場合は件数を不明として扱い、時間だけを表示する。

## 設定10項目

| 区分 | キー |
| --- | --- |
| 運用設定 | `WEB_APP_URL`, `POST_TEXT_TEMPLATE`, `CLASSROOM_SEND_BATCH_SIZE`, `DRY_RUN`, `ENABLE_DISTRIBUTION_LOG` |
| 自動生成・内部認証 | `MONITOR_URL`, `TEST_STUDENT_URL`, `ADMIN_TOKEN` |
| 自動更新メニューが管理 | `AUTO_REBUILD_CACHE_ENABLED`, `AUTO_REBUILD_CACHE_INTERVAL_MINUTES` |

出題規則はLv.0〜8の実装で固定する。旧3段階の定数・許容誤差6項目と、使われない`ENABLE_ADAPTIVE_PROBLEM_SELECTION`は削除する。通常の設定保存でも再作成しない。モニター一覧・CSVのレベル欄もLv.0〜8のみ。

## 診断と補修

1. 「もるくえ！」→「⓪ 初期整備・保守」→「⓪-3 管理シートの構成を診断」で、不足、重複、旧項目、独自追加項目を確認する。診断は値を書き換えず、認証値や生徒情報をログへ出さない。
2. 「⓪-1 管理シートを作成・補修」で不足を追加し、既知の旧設定・旧集計12列を除去する。重複ヘッダー／設定キーは自動で片方を選ばず、書込み前に停止する。
3. 設定値・個別URL・保存済み解答・正誤は保持する。チェックボックスの入力規則は使用行だけに適用し、適用前の値・数式を戻す。過去のチェックボックス挿入が作った、他の全セルが空で数式もないFALSEのみの行は最後に値だけを消す。行番号は変えない。
4. 独自追加列・設定や検証シートは勝手に削除せず診断に表示する。検証シートは通常運用の正本ではない。

補修は生徒の保存と同じスクリプトロックを取得する。失敗後は原因を確認して再実行できる。シートを開く`onOpen`はメニュー作成だけを行い、補修・集計・Classroom同期を自動実行しない。

列順を変更しても、同期・ログ・集計は見出し名で対応付ける。見出しは改名しない。全初期化は別の破壊的操作であり、通常の補修には使用しない。

## 実装上の根拠

Googleの[`insertCheckboxes`仕様](https://developers.google.com/apps-script/reference/spreadsheet/range#insertCheckboxes())は既存値もFALSEへ設定するため、補修は`requireCheckbox`と`setDataValidation`を用いる。[簡易トリガーの制約](https://developers.google.com/apps-script/guides/triggers)に合わせ、`onOpen`はメニュー作成に限定する。

実験場では入力規則の設定時にも空セルへFALSEが補完されたため、元値・数式の復元と最後の空行整理まで実施する。ローカルテストもこの実機挙動を再現する。

## v4への更新

管理シートは10、設定は10のまま。集計は9レベル×3指標と、保存済み解答時点のオート進行JSON `autoProgress` を持つ53列。旧カリキュラム専用列は作らない。解答ログは24列を維持し、既存の `clientInfo` にサーバーが `curriculumVersion:4` とオート段階を記録する。ブラウザーによる偽装値は採用しない。

更新はソース・デプロイ反映後、①「管理シートを作成・補修」②「集計キャッシュを更新」③モニター更新の順。スプレッドシートを開き直すと新メニューが反映される。古いモニタースナップショットと差分集計状態は再使用しない。

更新前の解答・判定・行番号は保持し、全期間の取組量には含める。Lv.0〜8の成績・苦手チェック・オート昇格には新版の記録のみを使う。旧Lv.5/6の意味を変更して集計しない。初めて新版でオートを選ぶとLv.0から開始する。
