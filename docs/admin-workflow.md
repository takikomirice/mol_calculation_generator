# 管理操作の改善と評価（2026-09-06 / GAS v20）

管理者側の使い勝手を90点に近づけるため、一覧条件の選び直し、生徒ごとのレビューの開き直し、管理シートを探す手間を減らした。現時点では **90 / 100の暫定開発者評価** とする。外部審査や実際の授業での満足度の測定値ではない。長期運用と実際の先生による確認結果に応じて評価を見直す。

## 変わった操作

| 場面 | 改善後 |
| --- | --- |
| 授業の対象を絞る | Classroomは同名でもID別に選べる。「表示人数 / 全人数」と適用中の条件を常に確認できる。 |
| 再読み込みする | 同じタブではクラス・状態・表示形式・並べ替えなどを復元する。検索文字列や生徒の名前・履歴は保存しない。 |
| 一覧が空になった | 「絞り込みを解除」で全員の表示に戻せる。表示形式と並べ替えは保つ。 |
| 生徒を順にレビューする | 「次の生徒」「前の生徒」の1操作で移動する。正誤・レベル条件を保ち、「一覧の何人目か」も表示する。 |
| 管理作業の場所を探す | 「管理操作」に名簿準備・配付確認・設定・処理結果をまとめ、必要なシートを開ける。 |
| 特定の生徒のURLを確認する | レビューの「この生徒の管理」から、対象のトークン管理行・名簿行へのリンクを表示する。 |

配付、URLの再発行・停止、設定変更は、既存の管理スプレッドシートのメニューで行う。ガイドは移動先と手順を提示する。実際の操作前にリンク先の氏名を確認する。Web画面だけで一括配付まで完結する機能は追加していない。

## 待ち時間とデータ取得

絞り込み・並べ替え・一覧条件の保存はブラウザ内で処理する。管理リンクはガイドを開いたときだけ取得し、通常更新に通信を追加しない。次の生徒へ進むときは、その生徒の既存の履歴取得APIだけを呼ぶ。問題タイプ集計は従来どおり展開時に取得する。

新しい `getMonitorOperationLinks` は認証を最初に確認する。固定した6シートの移動先と、指定生徒が一致した2シートの行位置だけを返し、生徒URL・認証値・解答ログ本文は返さない。該当シートや生徒行がなければ、そのリンクは操作できない表示になる。

## 自動テスト

Windowsの `npm test` は **264件成功、失敗0件**。GAS反映前のスクリプトでも全件成功。実装コミット `603ce8d` の [GitHub Actions（Ubuntu）](https://github.com/takikomirice/mol_calculation_generator/actions/runs/34038653625) も成功。今回追加したブラウザ6件とサーバー1件で、次を検証した。

- 同名クラスの分離、再読み込み時の条件復元、解除、保存領域が使えない場合の継続。
- 前後の生徒への移動、絞り込み維持、遅れて届いた別生徒の応答を無視すること。
- 裏で一覧が更新されても確認順序を保ち、閉じると元の生徒のボタンにフォーカスが戻ること。
- 管理ガイドの必要時取得、失敗時の再試行、閉じた後の応答を無視すること。
- 390px幅、入れ子のダイアログ、Escape、危険な移動先の無効化。
- 認証に失敗した場合にスプレッドシートへ触らないこと。対象行の一致、欠落シート、書込みなし。

既存の採点・権限・保存・生徒画面のテストも成功。今回、生徒の問題生成・採点・保存の処理は変更していない。

## 実GAS v20で確認したこと

Chromeで通常モニターと既存の測定専用ページを実操作した。測定専用ページは架空10人・1,200解答で、通常の名簿・集計とは分離されている。

- 通常モニターの管理ガイドから「Classroom一覧を開く」を操作し、管理スプレッドシートが別タブで開くことを確認。
- 同じタブで再表示した後、Classroomと詳細表示が復元された。「絞り込みを解除」でクラス条件が解除され、詳細表示は保持された。
- 10人の一覧で「不正解・Lv.1」に絞り、1人目→2人目→3人目→2人目と移動。見出し・位置・問題の表示が切り替わり、条件が保たれた。
- 戻った生徒の問題を展開し、生徒の解答・正答・解説が表示されることを確認。
- 架空生徒の個別管理では、実際の名簿に行がないため対象行リンクが操作できない表示になることを確認。実在する対象行のリンクはローカルの合成データで検証した。

| 操作 | 通信全体の実測 |
| --- | ---: |
| 通常モニターの初回更新 | 7,480 ms（1回） |
| 全体の管理ガイド取得 | 1,305 ms（1回） |
| 生徒別の管理ガイド取得 | 3,274 ms（1回） |
| 次・前の生徒への履歴取得 | 2,023 / 3,036 / 2,303 ms（3回） |

ブラウザの `[GAS timing]` が記録した呼出しから成功応答までの時間で、描画完了時間ではない。標本が少ないためp95や常時の速度保証には使わない。通常更新を高速化した比較試験でもない。今回の管理導線では、一覧の再取得や同じ条件の選び直しを減らしている。[数値の記録](performance/2026-09-06-admin-workflow-v20.json)。

## 残る改善余地

- 実際の先生が1クラスで、名簿同期から配付、個別対応まで一通り使う確認。今回の検証ではClassroomへ送信せず、生徒URLも変更していない。
- 学期ごとの比較やクラス全体の苦手傾向を使った分析。現状の指標と個人レビューは利用できるが、これらの集計は今回追加していない。
- 多人数利用中の管理操作、長期にログが増えた場合、実機スマートフォンでの検証。今回の実測は単独の管理操作で、以前のv19の40人負荷測定をv20で再実施したものではない。

変更は `feat/admin-workflow-ux` で管理する。push時の [品質チェック](../.github/workflows/quality.yml) と、反映前の全テストを継続する。
