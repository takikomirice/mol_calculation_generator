# もるくえ！ v3.0.0

変更点は [v3.0.0 リリースノート](docs/releases/v3.0.0.md) を参照してください。

## アプリ概要

Google Apps Scriptで動く、Classroom連携型モル計算練習アプリです。教員がスプレッドシートメニューからClassroomの生徒名簿を取得し、生徒ごとの個別URLをClassroomのお知らせとして配付します。生徒は配付されたURLから1問ずつ練習し、解答結果はスプレッドシートへ記録されます。

授業中のWebモニター画面は、`WEB_APP_URL` から自動生成される `MONITOR_URL` で開きます。Webモニターの表示・履歴参照は読み取り中心で、生徒一覧、KPI、要フォロー生徒、直近履歴を確認するための画面です。表示モードを切り替えられ、番号・氏名は横スクロールしても固定表示され、見出しクリックで並び替えできます。`表示中一覧CSV` は現在の検索・絞り込み・ソート後の生徒一覧をブラウザ側で保存する軽量な表示用CSVで、解答ログ全履歴CSVや分析CSVではありません。`MONITOR_URL` と `TEST_STUDENT_URL` は先生用として扱い、生徒やClassroomには共有しないでください。アクセス範囲はWebアプリのデプロイ設定に加え、先生用URLの認証で制御します。通常運用はWebモニター、設定シート、onOpenメニュー、各管理シートで行います。Webモニターの更新操作は「更新」1つです。前回から増えた解答を差分集計して表示します。全件を再計算して整合性を修復する保守操作は、管理スプレッドシートの `⑨ 集計キャッシュを更新` にあります。

## ファイル構成

| ファイル | 用途 |
| --- | --- |
| `Code.gs` | Google Apps Script本体。管理シート作成、Classroom連携、トークン発行、URL配付、問題生成、採点、ログ記録を行います。 |
| `Student.html` | 生徒用画面。個別URLから開き、レベル選択、解答入力、正誤確認、直近10問正答率の確認を行います。 |
| `Monitor.html` | 授業中の教員用Webモニター。設定シートの `MONITOR_URL` で開き、表示・履歴参照、限定メンテナンス、表示中一覧CSVを扱います。 |
| `appsscript.json` | Apps Scriptの設定ファイル。権限、Classroom API Advanced Service、Webアプリ設定を管理します。 |
| `tests/` | 開発用の自動テストです。Apps Scriptへ貼り付ける必要はありません。 |
| `docs/admin-retirement.md` | 管理画面廃止の完了記録と移管済みの運用方針です。 |
| `運用手順.md` | 授業で使うときの詳しい手順書です。 |

ZIPで配付する場合も、手順書のファイル名は `運用手順.md` のままにしてください。ZIP作成時はUTF-8のファイル名を保持できる圧縮ツールを使い、解凍後にこの名前で表示されることを確認してから配付します。

`Admin.html` は廃止済みです。旧管理画面は復活させず、Webモニター、設定シート、`もるくえ！` メニュー、各管理シートで運用します。

## 公開範囲とセキュリティ

このリポジトリには実運用のスプレッドシート、Classroom、児童生徒情報、発行済みトークン、デプロイ済みWebアプリURLは含めません。個別URLとトークンは導入先のスプレッドシート上で発行・管理されます。

公開前提で、`node_modules/`、Playwrightの実行結果、ローカル編集設定、非公開の設計ファイルは管理対象外にしています。Apps Scriptをデプロイするときは、学校や組織のGoogle Workspaceポリシーに合わせてWebアプリのアクセス権限を確認してください。

## 開発用テスト

初回は依存関係をインストールします。`postinstall` でPlaywright用のChromiumも取得されます。

```powershell
npm install
```

通常の回帰テストは次のコマンドで実行します。Playwright smoke test も含まれます。

```powershell
npm test
```

本番反映する前に、[生徒画面高速化 実機検証手順](docs/student-fast-mode-verification.md) に沿ってテスト用GASとテスト用スプレッドシートで確認してください。未検証コードを本番GASへ貼らないでください。

画面が最低限開けるかだけを確認したい場合は、次のコマンドを使います。

```powershell
npm run test:playwright
```

## 教員モニターの更新

「更新」を押すと、解答ログの前回以降の追加分を集計し、現在の名簿・URLの有効状態・配付状況と合わせて表示します。「自動更新」も60秒ごとに同じ処理を行います。更新のたびに全件再集計する必要はありません。

画面には「○時○分に確認した解答を反映」と表示します。更新中はボタンを無効にして連打を防ぎ、元の一覧と検索条件を保持します。通信失敗時も一覧を消さず、同じ「更新」で再試行できます。通常更新に確認ダイアログは出しません。

初回・破損からの復旧・追加解答が多い場合は500行ずつ処理し、進捗を表示します。集計位置と途中結果は `モニターキャッシュ` にJSONを分割保存するため、画面を閉じても次回続行できます。このシートは自動生成するため直接編集しないでください。読み込み開始後の新しい解答は次回の更新で反映します。生徒の解答ログ保存処理は変更していません。

古い解答ログを手修正した場合は `⑨ 集計キャッシュを更新` を実行し、続いてモニターの「更新」で全履歴から復旧します。日常の更新と履歴参照はWebモニターで、ログや生データの管理・設定・配付・保守は各管理シートとメニューで行います。問題タイプ別の履歴も解答ログから最新の集計を取得します。

## 初期設定

### 1. スプレッドシートを作成する

Google Driveで新しいスプレッドシートを作成します。授業用に使うファイル名を付けてください。

例: `もるくえ_2026_化学基礎`

### 2. Apps Scriptを作成する

スプレッドシートで `拡張機能` -> `Apps Script` を開きます。

### 3. コードを貼り付ける

Apps Scriptエディタに、次のファイルを作成または上書きして貼り付けます。

| Apps Script側のファイル名 | このリポジトリのファイル |
| --- | --- |
| `Code.gs` | `Code.gs` |
| `Student.html` | `Student.html` |
| `Monitor.html` | `Monitor.html` |

### 4. appsscript.jsonを設定する

Apps Scriptエディタのプロジェクト設定で「`appsscript.json` マニフェスト ファイルをエディタで表示する」を有効にし、このリポジトリの `appsscript.json` の内容を貼り付けます。

主な設定内容は次のとおりです。

| 設定 | 内容 |
| --- | --- |
| 実行環境 | V8 |
| タイムゾーン | Asia/Tokyo |
| Classroom API | Advanced Serviceとして有効化 |
| Webアプリ実行権限 | 自分として実行 |
| Webアプリアクセス権限 | 学校の運用に合わせて設定 |

### 5. Classroom API Advanced Serviceを有効化する

Apps Scriptエディタで `サービス` から `Google Classroom API` を追加します。識別子は `Classroom` のままにします。

Classroomが取得できない場合は、Google Cloud側でClassroom APIが無効になっていることがあります。その場合は、Apps Scriptのプロジェクトに紐づくGoogle CloudプロジェクトでClassroom APIを有効化してください。

### 6. Webアプリをデプロイする

Apps Scriptエディタで `デプロイ` -> `新しいデプロイ` を選び、種類を `ウェブアプリ` にします。

| 項目 | 設定 |
| --- | --- |
| 実行するユーザー | 自分 |
| アクセスできるユーザー | 学校アカウントの範囲に合わせて設定 |

生徒がClassroomから開くため、アクセス権限は学校のGoogle Workspace設定に合わせます。校内アカウントだけで使う場合はドメイン内ユーザーに限定します。外部制限が必要な学校では、管理者のポリシーに従ってください。

デプロイ後に表示されるWebアプリURLを控えます。

### 7. 管理シートを作成・補修する

スプレッドシートに戻り、再読み込みします。メニューに `もるくえ！` が表示されたら、`⓪ 初期整備・保守` -> `⓪-1 管理シートを作成・補修` を実行します。この処理は既存データを保持したまま、必要な管理シートを作成し、不足している列を末尾に追加して、書式や入力規則を整えます。

初回実行時は権限確認が表示されます。Classroom名簿取得、Classroomへのお知らせ投稿、スプレッドシートへの書き込みを許可してください。

### 8. 設定シートで基本設定を確認する

設定変更は `設定` シートの `値` 列を直接編集します。各行の `説明` 列に、何を書く設定か、代表的な入力例、注意点を記載しています。初期設定値の編集と同期操作は onOpenメニュー と `設定` シートを併用します。

| 項目 | 内容 |
| --- | --- |
| `WEB_APP_URL` | デプロイ後に控えたWebアプリの元URL |
| `MONITOR_URL` / `TEST_STUDENT_URL` | `もるくえ！` -> `★ 先生用URLを設定シートに出力` で自動出力される先生用URL |
| `POST_TEXT_TEMPLATE` | Classroomへ投稿する本文テンプレート。必ず `{{studentUrl}}` を含めます。主な差し込み項目は `{{氏名}}`、`{{出席番号}}`、`{{Classroom名}}`、`{{studentUrl}}` です。 |
| `DRY_RUN` / `CLASSROOM_SEND_BATCH_SIZE` / `ENABLE_DISTRIBUTION_LOG` | 配付確認、本送信、ログ記録の設定 |
| `AUTO_REBUILD_CACHE_ENABLED` | 集計キャッシュ、問題タイプ別キャッシュ、モニターキャッシュの自動更新ON/OFF。デフォルトは `false` です。 |
| `AUTO_REBUILD_CACHE_INTERVAL_MINUTES` | 自動更新間隔。通常は5分程度を推奨します。 |
| レベル別アボガドロ定数・許容誤差 | 初級・中級・上級の問題生成と採点に使う値 |

`WEB_APP_URL` を入力したら、`もるくえ！` -> `★ 先生用URLを設定シートに出力` を実行します。設定シートに `MONITOR_URL` と `TEST_STUDENT_URL` が出力されます。この処理の完了時に、既存キャッシュから `モニターキャッシュ` の `dashboard` 行をbest-effortで初期作成します。通常は `MONITOR_URL` を開くとすぐWebモニターを確認できます。`MONITOR_URL` は授業中モニター用、`TEST_STUDENT_URL` は先生が生徒画面をテストプレイするためのURLです。どちらも先生用として扱い、生徒やClassroomには共有しないでください。Webモニターのアクセス範囲はWebアプリのデプロイ設定に加え、先生用URLの認証で制御します。学校内で使う場合は、デプロイ時の「アクセスできるユーザー」を学校/組織内ユーザーにします。Webモニターの更新操作は「更新」1つです。前回から増えた解答を差分集計して表示します。全件を再計算して整合性を修復する保守操作は、管理スプレッドシートの `⑨ 集計キャッシュを更新` にあります。

## Webモニターとメニュー操作

初期設定値の編集は `設定` シート、同期操作は onOpenメニュー として表示されるスプレッドシートの `もるくえ！` メニューから行います。通常運用はWebモニター、設定シート、onOpenメニュー、各管理シートで完結します。

授業中は設定シートの `MONITOR_URL` を先生が開きます。生徒画面の動作確認は設定シートの `TEST_STUDENT_URL` を開きます。どちらも `もるくえ！` -> `★ 先生用URLを設定シートに出力` で更新できます。`TEST_STUDENT_URL` は先生用テストプレイURLであり、Classroomには配付しません。`MONITOR_URL` も先生用であり、生徒には共有しないでください。Webモニターのアクセス範囲はWebアプリのデプロイ設定に加え、先生用URLの認証で制御します。Webモニターの表示・履歴参照は読み取り中心です。表示モードで標準、フォロー、詳細、配付確認を切り替えられ、番号・氏名は横スクロールしても固定表示され、見出しをクリックすると並び替えできます。必要に応じて手動更新するか、画面上部の自動更新をONにすると60秒ごとに再読み込みします。この60秒自動更新も「更新」と同じ差分集計を行い、最新の解答を反映します。処理中は次の更新を重ねません。

通常表示ではライブ構築せず、先生が明示的にボタンを押したときだけ更新します。status lineにも次に押すべきボタンを表示します。必要に応じて `管理スプレッドシートを開く` から同じ管理ブックを別タブで確認できます。トークン再発行、URL無効化、Classroom投稿削除、自動更新ON/OFF、初期化などはWebモニターからは実行できません。Webモニターの更新操作は「更新」1つです。前回から増えた解答を差分集計して表示します。全件を再計算して整合性を修復する保守操作は、管理スプレッドシートの `⑨ 集計キャッシュを更新` にあります。

`表示中一覧CSV` は、現在の検索、Classroomフィルター、状態フィルター、フォロー絞り込み、未実施絞り込み、ソート後の生徒一覧をブラウザ側でUTF-8 BOM付きCSVとして保存する軽量機能です。サーバー側CSV生成や解答ログ読み込み、スプレッドシート書き込みは行いません。CSVは表示中の生徒一覧用の表示用CSVであり、解答ログ全履歴CSV、問題タイプ別詳細CSV、分析CSVではありません。苦手傾向分析や苦手傾向Classroom通知も今回の対象外です。Classroom取得、生徒名簿取得、トークン発行、URL配付、投稿削除、管理データ初期化などの準備・設定・配付・保守は `もるくえ！` メニュー側で行います。ログや生データは `解答ログ`、`配付ログ`、`実行ログ` などの各管理シートで確認します。

個別対応は `トークン管理` シートで対象行を1行だけ選択して、`もるくえ！` -> `④ 個別対応` から行います。教師プレビューは `④-1 選択行の教師プレビューURLを表示`、個別トークン再発行は `④-2 選択行のトークンを再発行`、個別URL無効化は `④-3 選択行のURLを無効化` を使います。個別再発行や無効化ではClassroom投稿は自動更新・自動削除されません。Classroom投稿削除も必要な場合は、従来通り `トークン管理` の `投稿削除` に `1` を入力して `③ 投稿・URL取消` を使います。

授業中にモニター反映を定期更新したい場合は、`⑤ 自動更新` -> `⑤-1 集計・モニター自動更新を有効化` を使います。通常は5分程度を推奨します。`⑤ 自動更新` はフル更新系であり、生徒の採点レスポンスとは別実行で、指定間隔ごとに `集計キャッシュ`、`問題タイプ別キャッシュ`、`モニターキャッシュ` を更新します。自動更新を止めたい場合は `⑤-2 集計・モニター自動更新を停止`、状態確認は `⑤-3 自動更新の状態を表示` を使います。生徒画面は常時高速ルートで動くため、採点直後の反映は遅れることがありますが、生徒の体感速度を優先する設計です。Webモニターの更新操作は「更新」1つです。前回から増えた解答を差分集計して表示します。全件を再計算して整合性を修復する保守操作は、管理スプレッドシートの `⑨ 集計キャッシュを更新` にあります。

授業前の通常フローは、`① Classroom同期` -> `② 生徒URL` -> Webモニター確認です。各メニューの実行後は結果がalertで表示されます。

1. 必要なときだけ `⓪ 初期整備・保守` -> `⓪-1 管理シートを作成・補修`
   最初の1回、アップデートで列が増えたとき、シート構成が壊れたときに使います。既存データを保持し、不足している列は自動で末尾に追加されます。

2. `設定` シートの `値` 列を確認
   `説明` 列を参考に、WebアプリURL、投稿文、配付設定、出題・採点設定を確認します。`WEB_APP_URL` を設定したら `★ 先生用URLを設定シートに出力` を実行し、`MONITOR_URL` と `TEST_STUDENT_URL` を確認します。完了時にモニター表示用キャッシュもbest-effortで初期作成されるため、通常は `MONITOR_URL` をすぐ確認できます。どちらも先生用として管理し、生徒には共有しません。

3. `① Classroom同期` -> `①-1 Classroom一覧を取得`
   教員アカウントが担当しているClassroomを取得します。

4. `① Classroom同期` -> `①-2 同期対象の説明を表示`
   今回使うClassroomだけを同期対象にします。Classroom一覧の `同期対象` は `1` でON、空欄でOFFです。

5. `① Classroom同期` -> `①-3 生徒名簿を取得`
   同期対象Classroomの生徒を取得し、`生徒名簿` シートへ反映します。

6. `② 生徒URL` -> `②-1 トークンを発行`
   生徒ごとの個別URLを作成します。URLは本人専用です。

7. `② 生徒URL` -> `②-2 配付対象を確認` / `②-3 DRY_RUNでURL配付確認`
   Classroomに投稿せず、配付対象とログだけを確認します。本送信前に必ず実行してください。

8. `② 生徒URL` -> `②-4 URLをClassroomに配付`
   同期対象Classroomの生徒へ、Classroomのお知らせとして個別URLを配付します。

9. `② 生徒URL` -> `②-5 失敗分を再送`
   配付ログで失敗が残った場合だけ実行します。

10. `★ 先生用URLを設定シートに出力` / `⑨ 集計キャッシュを更新`
   授業中確認は設定シートの `MONITOR_URL`、生徒画面の動作確認は `TEST_STUDENT_URL` を使います。ログや生データ確認は `解答ログ`、`配付ログ`、`実行ログ` などの各管理シートを使います。

危険操作の `管理データを全削除して初期状態に戻す` は、`⓪ 初期整備・保守` にある管理データを削除するメニューです。通常の作成・補修とは違い、授業データを残したい場合は実行しないでください。

誤配付や配付取り消しをする場合は、`トークン管理` シートで対象生徒の `投稿削除` に `1` を入力し、`もるくえ！` -> `③ 投稿・URL取消` -> `③-1 投稿削除=1 のURLを無効化してClassroom投稿を削除` を実行します。このメニューでは、対象生徒のURLを無効化し、対応するClassroom投稿を削除します。解答ログや集計データは削除しません。

`revoked` は、空欄 = 有効、`済` = 無効化済みです。既存の 1 や TRUE、チェックボックス由来の値も無効として読み取られますが、今後システムが無効化済みとして書く値は `済` です。

`投稿削除` は、空欄 = 対象外、`1` = 次回メニュー実行時の削除対象、`済` = 投稿削除済み、`失敗` = 投稿削除に失敗、`対象なし` = 対応するClassroom投稿が見つからなかったがURL無効化は済み、という意味です。`済`、`失敗`、`対象なし` は次回の削除実行対象にはしません。再実行したい場合は、先生が `投稿削除` を再度 `1` に書き換えてください。チェックボックスではなく、文字入力で運用します。

トークン無効化とClassroom投稿削除は別概念です。ただし、`投稿削除=1 のURLを無効化してClassroom投稿を削除` メニューでは、対象URLの無効化と対応するClassroom投稿削除をまとめて実行します。削除結果は `トークン管理` の `revoked` / `投稿削除` / `note`、配付ログ、実行ログに残ります。行は削除せず、履歴として残します。元の `SUCCESS` 配付ログ行は削除せず、削除処理の結果として `DELETED`、`DELETE_ERROR`、`DELETE_SKIPPED` の行を追記します。解答ログや集計データは削除しません。先生向けの説明や入力例では `6.02×10^23` または `6.02x10^23` の形を使い、e表記例は出しません。

## 高速化後の設計概要

- token検索の高速化: 生徒URLアクセス時は `トークン管理` のtoken列を検索し、トークン表全体の読み込みを避けます。
- 生徒画面の常時高速ルート: 生徒APIの通常/高速切替設定は存在しません。授業中の快適性を優先し、初回表示時の `lastAccessedAt` 即時書き込みは行わず、token情報の短時間キャッシュを常に使います。採点レスポンスは正誤、正答、解説の返却を優先し、解答ログは正本データとして同期保存します。
- 生徒APIの軽量化: 初回表示、問題取得、採点では管理シート全体チェック、集計キャッシュ読み書き、問題タイプ別キャッシュ読み書き、解答ログ全読みを避けます。生徒別summaryはキャッシュを使い、キャッシュがない場合は本人の保存済み解答ログから復元します。
- モニター反映: 常時高速ルートではWebモニターの「アクセス済み」、解答数、直近10問正答率などの集計反映が少し遅れることがあります。Webモニターの更新操作は「更新」1つです。前回から増えた解答を差分集計して表示します。全件を再計算して整合性を修復する保守操作は、管理スプレッドシートの `⑨ 集計キャッシュを更新` にあります。
`★ 先生用URLを設定シートに出力` の完了時にも、既存キャッシュからこのスナップショットをbest-effortで初期作成します。`モニターキャッシュ` は自動生成の表示用キャッシュで、先生が直接編集しないでください。正本データは `解答ログ`、`トークン管理`、`生徒名簿`、`配付ログ` です。スナップショットが壊れても正本データから再生成できます。Webモニターの更新操作は「更新」1つです。前回から増えた解答を差分集計して表示します。全件を再計算して整合性を修復する保守操作は、管理スプレッドシートの `⑨ 集計キャッシュを更新` にあります。
- 集計・モニター自動更新: `⑤ 自動更新` から任意で有効化できます。デフォルトはOFFです。授業中に使う場合は5分程度を推奨し、時間トリガーで `集計キャッシュ`、`問題タイプ別キャッシュ`、`モニターキャッシュ` を更新します。Webモニター表示時や生徒の採点時には書き込み処理を戻しません。
- 採点レスポンスの軽量化: 採点中は重複チェックと `解答ログ` 追記だけを同期で行い、`集計キャッシュ` と `問題タイプ別キャッシュ` は読み書きしません。集計や苦手傾向は `⑨ 集計キャッシュを更新` または `⑤ 自動更新` で整えます。
- 適応出題: 生徒リクエスト中は問題タイプ別キャッシュを読まず、通常ランダム出題を優先します。授業中の軽さを優先し、正確な問題タイプ別反映は後処理に寄せます。
- 生徒画面の次問先読み: 2問目以降は同じレベルの次問を解答中に先読みするため、次の問題へ進む体感速度が改善します。採点レスポンスでは原則 `nextProblem` を同梱せず、プリフェッチ済み問題を使うか、なければ次問ボタン押下時に `getPracticeProblem` で取得します。プリフェッチ済み問題には直前の解答結果が反映されない場合があります。
`表示中一覧CSV` は現在の表示・絞り込み結果だけをブラウザ側で保存する軽量な表示用CSVで、解答ログ全履歴CSVや分析CSVは対象外です。モニターが遅い場合はApps Scriptログの `getMonitorDashboardData elapsedMs`、`cacheReadElapsedMs`、`sheetReadElapsedMs`、`jsonParseElapsedMs`、`rowCount`、`payloadBytes`、`liveFallback=false` を確認します。苦手傾向分析、苦手傾向Classroom通知、分析CSVは今後の別機能として扱います。Webモニターの更新操作は「更新」1つです。前回から増えた解答を差分集計して表示します。全件を再計算して整合性を修復する保守操作は、管理スプレッドシートの `⑨ 集計キャッシュを更新` にあります。

## 生徒画面の使い方

生徒には次のように案内してください。

1. Classroomのお知らせから、自分専用のURLを開く。
2. 名前が表示されていることを確認する。
3. `Lv.1`〜`Lv.6` からレベルを選ぶ。Lv.1／3では練習する変換も選ぶ。
4. 問題文を読み、数値だけを入力する。
5. `答える` を押して正誤と解説を確認する。
6. 続けて解く場合は次の問題へ進む。
7. 画面に表示される直近10問正答率を確認する。

URLは本人専用です。他の生徒と共有しないように伝えてください。

## 問題レベル

| レベル | 内容 |
| --- | --- |
| Lv.1 | mol ⇔ 質量・個数・体積のうち1種類を選択。簡単な計算。 |
| Lv.2 | Lv.1の範囲をランダム出題。簡単な計算。 |
| Lv.3 | 質量 ⇔ 個数、質量 ⇔ 体積、体積 ⇔ 個数のうち1種類を選択。簡単な計算。 |
| Lv.4 | Lv.3の範囲をランダム出題。簡単な計算。 |
| Lv.5 | Lv.2の範囲で計算を少し難しくし、有効数字3桁で解答。 |
| Lv.6 | Lv.4の範囲で計算を少し難しくし、有効数字3桁で解答。 |

Lv.1〜4はアボガドロ定数 `6.0×10^23`、Lv.5〜6は `6.02×10^23` を問題文に示します。気体の体積は標準状態（0 ℃・1 atm）、モル体積22.4 L/molです。Lv.5〜6は、表示された数値を使って計算し、答えを有効数字3桁に丸めます。`1.20` と `1.2` の桁数を区別し、数値だけ合う場合は桁数を直す案内を表示します。Lv.1〜4は数値が一致すれば末尾の0を問いませんが、整数への大きな丸めは正答にしません。

旧初級・中級・上級のログとAPIは互換性のため維持します。設定シートの旧レベル別定数・許容誤差は旧API用であり、Lv.1〜6の上記ルールは固定です。

## 100人規模運用時の注意

- 授業前にトークン発行とURL配付を済ませてください。授業開始直後にClassroom送信を集中させない方が安定します。
- 生徒画面は常時高速ルートで動きます。初回アクセス時刻や集計の即時モニター反映より、生徒画面の初回表示と採点体感を優先します。
- 本番反映前は `docs/student-fast-mode-verification.md` の手順でテスト用GASを確認してください。問題があれば実機ログで原因を切り分け、必要に応じて直前の安定デプロイへ戻します。生徒APIの通常/高速切替設定は存在しないため、切り戻しは安定デプロイへの戻しで行います。
- URL配付は必ず `DRY_RUN` で対象人数と内容を確認してから本送信してください。
- 授業中に `①-1 Classroom一覧を取得`、`①-3 生徒名簿を取得`、`②-4 URLをClassroomに配付`、`⑨ 集計キャッシュを更新` などの重い処理を連打しないでください。
- 授業中に自動更新を使う場合は5分程度を推奨します。授業後や不要時は `⑤-2 集計・モニター自動更新を停止` で停止してください。
- 解答ログ書き込みには `LockService` を使っています。同時アクセス時の重複書き込みや競合を抑えるためです。
- 同時送信が多い場合、Google側の一時的な制限で失敗する可能性があります。生徒画面には再送できるUIを用意しておき、失敗時は時間を置いて再実行してください。
- 配付ログで `ERROR` が残った場合は、`②-5 失敗分を再送` で失敗分だけ再送してください。

## トラブルシュート

### Classroomが出ない

- ログインしているGoogleアカウントが、対象Classroomの教師になっているか確認してください。
- Apps Scriptの `Google Classroom API` サービスが追加されているか確認してください。
- Google Cloud側でClassroom APIが有効になっているか確認してください。
- 初回認可でClassroom関連の権限を許可したか確認してください。

### 生徒名簿が取れない

- `Classroom一覧` で同期対象にチェックが入っているか確認してください。
- 対象Classroomに生徒が参加済みか確認してください。
- Classroomの名簿取得権限がある教員アカウントで実行してください。

### URL配付に失敗する

- まず `DRY_RUN` で配付対象が正しいか確認してください。
- `トークン管理` に `studentUrl` が作成されているか確認してください。
- Classroom APIの投稿権限が許可されているか確認してください。
- `配付ログ` の `errorMessage` を確認し、`②-5 失敗分を再送` を実行してください。

### 生徒がアクセスできない

- Webアプリのアクセス権限が、生徒のGoogleアカウントで開ける設定になっているか確認してください。
- 生徒がClassroomで使っている学校アカウントでログインしているか確認してください。
- 古いデプロイURLを配付していないか確認してください。

### token不正と出る

- Classroomのお知らせにある本人専用URLを開いているか確認してください。
- `トークン管理` で該当生徒の `revoked` が `済` になっていないか確認してください。`revoked` は空欄で有効、`済` で無効化済みです。既存の 1 や TRUE も無効として読み取られます。
- トークンを再発行した場合は、新しいURLを再配付してください。

### 解答が記録されない

- `解答ログ` シートが存在するか確認してください。
- Apps Scriptのスプレッドシート書き込み権限が許可されているか確認してください。
- 生徒画面にエラーが出た場合は、時間を置いて再送してください。
- `実行ログ` やApps Scriptの実行ログでエラー内容を確認してください。

## 補足

- Webアプリは「自分として実行」するため、Classroomへの投稿やスプレッドシートへの記録はデプロイした教員アカウントの権限で行われます。
- 生徒ごとのURLにはトークンが含まれます。URLを知っている人がアクセスできる設定にする場合でも、トークン管理により本人用の画面として扱います。
- 運用の詳しい流れは `運用手順.md` を参照してください。


## 検証環境と6レベルへの更新

[検証環境の手順](docs/gas-test-environment.md) に従って `scripts/deploy-test-gas.ps1` を実行すると、テスト成功後に同じWebアプリURLへ反映します。

更新後はスプレッドシートの「⓪-1 管理シートを作成・補修」で新しい集計列を追加し、「★ 先生用URLを設定シートに出力」で認証付き `MONITOR_URL` を再発行してください。以前の認証なしモニターURLは開けなくなります。「⑨ 集計キャッシュを更新」で新しい形式のモニターキャッシュを作成します。定期更新を使っていた場合は「⑤-1 集計・モニター自動更新を有効化」を再実行し、Web画面から呼べない内部トリガーへ移行してください。

生徒の総解答数・直近10問は保存済みログを元に復元し、通常は生徒ごとのキャッシュから取得します。解答の追記と集計更新を同じロック内で行い、再送による二重加算を防ぎます。キャッシュが消えた場合だけ、生徒別ログを読み直します。


## 改善の品質確認

ブランチへのpush・pull requestでは [品質チェック](.github/workflows/quality.yml) が `npm test` を実行します。採点・権限・復旧の検証と、架空データを使ったChromium操作が対象です。Googleの認証情報はCIに渡しません。

検証用GASへの反映は `scripts/deploy-test-gas.ps1` が全テストと反映先を確認して実施します。実際のGASでの採点測定、事前に定めた判定基準、実測結果は [90点に向けた評価記録](docs/readiness-90.md) にまとめています。CIのローカル測定をGASの実速度として扱わず、実測JSONを `npm run check:student-load -- <path>` で判定します。


管理者の「管理操作」は目的別のシートへの入口です。詳細レビューの「この生徒の管理」からは対象行へ移動できます。レビューは前後の生徒へ続けて移動し、同じ絞り込み条件で確認できます。手順は [運用手順](運用手順.md#管理操作を短い手順で進める) を参照してください。

管理操作の変更点・実測・残る制限は [管理操作の評価記録](docs/admin-workflow.md) を参照してください。
